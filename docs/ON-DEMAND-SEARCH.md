# v0.77 検索時に公式ディスコグラフィーを確認する設計

事前生成済みの目次を探す方式から、入力されたアーティストについて検索時に公式資料を取得・検証する方式へ変更。ブラウザ→検索API→公式ディレクトリ/公式作品ページ→発売確認→SQLite保存→表示。以前のJSON目次とMusicBrainzは検索結果にも判定根拠にも使用しない。

## 公式情報源と探索

信頼設定は `data/official-realtime.json`。レコード会社の許可ホスト、公式ディレクトリの形式、既知のアーティスト公式サイトの運営主体・名義対応だけを持ち、作品リストは持たない。

- Blue Noteの公式アーティスト一覧を入力名と照合し、本人Releasesを取得。
- Warner Music Japanの公式アーティスト検索一覧を照合し、本人ディスコグラフィーを取得。
- Sony Music Japanの公式ディレクトリと既知の本人ディスコグラフィーを取得。取得できても必要な発売情報がHTML内にない場合は「発売根拠が不足」として扱う。
- アーティスト公式は確認済みの公式ドメインを信頼設定から利用。ジミ公式Musicページでは作品ページを辿り、作品の発売日フィールドを検証する。

未知の名義でもレコード会社の公式一覧から見つかれば、その場で作品を確認できる。任意のアーティストの個人ドメインを名前から推測したり、非公式検索結果から自動で公式認定したりしない。世界中のすべての公式サイトを発見する検索エンジンではない。公式サイトが存在しないとは断定せず、探索した公式資料の範囲で確認できなかった旨を表示する。

## 掲載と発売済みの区別

| 情報源の形式 | 正式発売を確認するための必須条件 |
|---|---|
| Blue Note | 本人h1、本人だけへの名義リンク、公式Releasesのrelease-entry、発売済みと判断できる過去の掲載発売年 |
| Warner | 本人見出し、ALBUM区分、本人の商品URL、明示的な「発売」日が当日以前 |
| 公式MusicAlbum JSON-LD | 本人byArtist、AlbumRelease、MusicRelease、発行レーベル、当日以前の発売日、許可された根拠URL |
| ジミ公式の音楽作品ページ | 本人名義、music-title、明示的なmusic-release-date、音楽のトラック欄、発行元、音楽アルバム/CD/レコードの形式情報 |

公式URLに掲載されているだけのリンク・記事・ニュース、出演情報、記事公開日、録音年からは昇格しない。Blue Noteの当年分は日が分からないため一旦保留。初回発売年と国別再発日を混同しないよう、自動検証の作品はyear=null、発売済みの根拠になった日付/年をgenerationProofに保存する。

ジミのHTMLアダプターは実際の公式ページで確認したmusic-release-dateを使い、datePublishedのような記事公開タイムスタンプは使わない。1検索で最大6作品ページを検証するため、全作品を網羅しない。アルバム名・公式URL・取得ハッシュ・名義ID・検証ルールを保存する。ハッシュは取得内容の指紋であり、署名による真偽保証ではない。

## 保存と再検索

SQLiteは空から開始し、確認できた作品だけを保存。事前目次からの自動投入は行わない。日本語/英語の既知別名は同じキャッシュへ対応付ける。

有効期間は作品ごとに24時間。再検索は期限内の保存結果を返し、UIにも再利用と表示する。明示的な再確認が失敗した場合は、有効な保存結果だけを確認日時・有効期限を延長せずに表示する。期限切れや根拠が壊れたレコードは表示せず、元のDBを誤って削除しない。

確認できなかった検索や取得失敗を「確認済み0件」として永続保存しない。HTTP 401/403/429と明示的なアクセス拒否ページはblocked、ネットワーク・文字コード・サーバー障害はfetch_errorなどに分ける。拒否ホストは180秒のクールダウン。IP変更、User-Agent偽装・ローテーション、認証回避、別ホストへの転送追従は行わない。通常の固定RECORD User-Agentを使用する。

## APIと表示状態

| status | 意味 |
|---|---|
| confirmed | 取得できた公式資料から発売確認済み作品あり |
| partial | 確認済み作品あり。一部取得失敗、または再確認失敗後の有効な保存結果 |
| not_found | 検索した公式情報源で名義/発売情報を確認できず。サイトの不存在とは断定しない |
| unconfirmed | 公式資料は取得したが、発売済みアルバムの必須根拠が揃わず |
| blocked | アクセス制限のため取得できず。公式情報なしとは扱わない |
| fetch_error | ネットワーク・形式・サーバー障害等で取得/検証できず |
| service_unavailable | APIに接続できない/処理できない。公式サイト側の失敗とは別表示 |

入力名から外部URLを自由取得するAPIではない。公式プロバイダーの許可ホスト・パスだけに通信し、同じ検索の同時実行を共有し、同時処理数と取得件数を制限する。GETのみ。ソースコード・SQLite・過去の静的目次をWebサーバー経由で配信しない。外部文字列はDOMのtextContentで表示する。

ブラウザは検索世代を管理し、前の検索の遅い応答で新しい結果を上書きしない。APIが使えない場合も、事前目次やMusicBrainzへ戻らない。既存の保存記録とバックアップ/復元は残す。

ジミの3作品はHollywood Bowl August 18, 1967、Los Angeles Forum: April 26, 1969、Live In Maui。マイルスはBlue Noteの2作品とWarnerの10作品。Sony/Columbia全作品を取得できたという意味ではない。Sonyの一部ページはHTMLだけでは必要情報を抽出できず、未確認のまま。診断は [ON-DEMAND-LIVE-2026-10-27.json](ON-DEMAND-LIVE-2026-10-27.json)。初回は複数公式ページの取得が必要なため時間がかかる。次回は確認結果のキャッシュを利用する。
