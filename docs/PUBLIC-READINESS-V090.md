# RECORD v0.90：無料構成での公開前準備

2026-10-27（日本時間）。PR #36・#37を継承。事前登録は20組・292作品、Miles Davisは72作品、確認済みYouTube Music直接リンク6件を変更していない。公開Pagesの既定はcatalog、API URL空欄。本番登録・デプロイ・秘密情報登録・課金は未実施。

## 選んだ構成と到達点

**GitHub Pages + Render Freeの単一Python API**を、次の許諾済み小規模試験に向けた準備対象として選定した。Pythonの既存パーサー・証拠照合・日英別名探索を使えるため、移植による認定漏れのリスクと保守負担が少ない。外部DBは作らず、一時SQLiteで確認済み結果を最大24時間再利用する。無料本番の実用性や常時安定稼働を保証する選定ではない。

`render.yaml` を旧DB必須案から、Free / Python / 1インスタンス / 1ワーカー / 4スレッド / 自動デプロイoffに更新した。`server/requirements-free.txt` はGunicornのみ。`server.public:create_public_app()` を起動する。APIは `/health` と `/api/search` のみ。Pages自体はRenderへ移さない。設定をリポジトリに置くだけではリソースは作成されないが、Blueprintの初回適用はサービス作成・公開デプロイとなるため承認後に限る。

**現在の設定ではWillie Nelsonのライブ作品は0件で、利用条件確認待ちを表示する。** v0.89で技術的に2作品を取得できたことと、公開サービスとしての自動取得・再利用の許諾は別である。未確認の取得元は無理に取得しないという今回の指示に合わせ、Warner・Blue Noteも保留にした。サービスへ登録するだけで未登録検索が利用可能になる状態ではない。

## 取得元の規約と停止条件

`data/official-access-policy.json` を追加。全取得元は `review_required` または `prohibited` であり、許可済みの取得元は現時点ではない。未知ホストも拒否する。Sonyの禁止対象は従来どおり固定停止。一般robots許可を、公開用途の取得・再利用許可と解釈しない。

- [Sony利用規約](https://www.sonymusic.com/terms-and-conditions/)：自動取得の制限。Jimi/Miles本人サイト・Sony関連取得元は停止を維持。
- [Universal規約](https://privacy.umusic.com/terms/)：Blue Noteのリンク先。個人・内部利用や再利用の制限がある。今回の公開自動取得を許可する根拠が不足。
- [Warner Japan規約](https://wmg.jp/corporate/terms-of-use)：今回の公開自動取得・メタデータ再利用を許可する根拠が未確定。

許可を記録するには、発行元による許諾・適用条件の根拠URL、確認日時、有効期限（最大90日）、`public-automated-release-metadata` の用途をレビューして設定する。ユーザーのデプロイ承認だけでは発行元の許可にならない。禁止対象の解除は別途根拠とコードレビューが必要。期限切れ・撤回時はキャッシュも表示しない。設定ファイルは許諾そのものを生成する仕組みではない。

通常transportは規約許可を確認してからrobotsへ接続する。PR #36の旧HTTP・CORS調査スクリプトも未確認ホストへ再接続しないよう停止条件を追加し、CIも許可待ち状態の検証へ変更した。規約の確認は資料閲覧のみで、ディスコグラフィーのライブ再取得はしていない。

## アクセス負荷・保存・エラー

- API全体10検索/分、同時検索は既存最大4。同じ検索の実行を集約、否定結果は既存の短期キャッシュを利用。CORSはPagesの正確なOriginのみ。Originなしも拒否。ただし非ブラウザからの偽装は防げず、認証を実装したという意味ではない。
- 公式への送信は全ホスト合計100要求/UTC日。robots・転送も計上。ホストごと1秒間隔・1同時通信、固定識別UA、12秒タイムアウト、5MB上限。401/403/429・チャレンジ応答でホスト停止。迂回・別IP・UA変更なし。
- 新規一時SQLiteには翌UTC日までの取得停止を記録する。同じファイルを使うワーカー再起動では予算を保持。休止等でファイルが消えた場合、その日の再取得は停止し、同日の予算を再発行しない。1インスタンス/1ワーカーが前提。複数サービスの作成は全体上限を共有しないため不可。
- **この保護の代償として、初回起動日・データ消失日は未知アーティストの取得ができない。** Renderの休止で繰り返し消えるため、これは一般公開の快適な運用には大きな課題。再起動をまたぐ永続の取得予算/キャッシュを無料で確保する方式が、広い公開の前に残る。今回別サービスやDBは導入していない。
- 確認済み結果だけ最大24時間保存。クエリー別名も再利用。期限を延長して古い作品を正規盤と認定し続けない。公開APIのrefresh指定は強制再取得にせず通常の有効期限・キャッシュを守る。保存は一時的で永続保存ではない。利用者自身の保存・バックアップ・復元は従来のブラウザ機能のまま。
- 利用条件による停止、HTTP制限、通信失敗、取得予算不足、根拠不足を診断で区別。取得予算不足はsourceの `budget_exhausted`、規約未確認は `policy_restricted`。失敗をMusicBrainzのOfficial表記や推測リンクで補わない。画面のタイムアウト・起動待ち案内は既存機能を維持。
- 任意URLは入力不可、HTTPS公式ホストのみ、転送先検証、資格情報なしのfetch。API鍵をPagesに置かない。APIには画面/ソース/秘密ファイルを配信させず、内部例外を応答へ出さない。不要なGunicorn制御ソケットは無効化。Gunicornアクセスログは有効化せず、検索文字列の不要な記録を避ける。Render側のログ・アクセス制御は初回設定時にも確認が必要。

## 公開までの手順

今すぐサービスを作る必要はない。まず取得元の公開自動取得・再利用条件を解決し、永続の取得予算/キャッシュを無料で確保する方式を確定する。これらが解決するまでは、公開Pagesのcatalogを維持する。

ユーザーによる操作が必要になるのは、(1)権利者への許諾申請で本人による同意等が必要な場合、(2)構成確定後のRender無料アカウント本人認証/GitHub接続と、サービス作成・公開デプロイの明示承認、のみ。承認後の作業はAPIの `/health`・CORS・対象検索を確認し、実際のAPI HTTPS Originを使い以下でPagesのhybrid構成を生成する（本PRでは未適用）。

```sh
python scripts/configure_public_api.py https://APPROVED-API-ORIGIN --mode hybrid --output /tmp/record-hybrid.html
```

生成差分をPRで確認後、Pagesへ適用しiPhone実機で未知検索と既存目次を確認する。ロールバックはmetaをcatalog/API空欄へ戻す。支払情報・有料プラン・外部DBはこの手順に含めない。権利者許可や永続上限の未解決をデプロイ承認だけで省略しない。
