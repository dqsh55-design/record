## 実現したこと

Pagesと同じ画面で、登録済みアーティストは従来の目次、未登録アーティストは公式取得APIへ問い合わせるhybridモードを実装した。本人・レコード会社の公式資料から確認できた作品だけ、作品名・発売年・発売元・公式根拠URLを表示する。新規のYouTube Music直接リンクは検証していないため、従来の作品名検索を使う。

公開 `index.html` の既定モードはcatalogのまま。API URLも空のまま。hybridは試作品・承認後の構成生成に限る。したがって、このPRのマージだけで公開サイトの未登録検索が動くとは説明しない。

既存 `server/search.py` の公式ディレクトリー探索、照合、24時間の確認済みキャッシュ、重複要求の集約、取得予算を再利用。Willie Nelson用のアーティスト登録・アルバム登録は追加していない。公式一覧の同じURLにある日本語／英語ラベルを保持し、別名義の取り違えを防ぎながらWarnerの日本語見出しにも対応した。WarnerはALBUM専用ページを取得する。

API結果と公開目次を別々に保持するため、Willie Nelsonを表示した後でもMiles Davisの既存72作品、Norah Jonesの既存13作品や直接リンクを失わない。全体の「登録292作品」はAPIの一時結果を加算しない。新しい検索より遅く届いた古い応答で画面が戻る問題も防止した。

## 利用規約・robots・アクセス制限

[確認記録](experiments/v089-source-policy-2026-10-27.json)。Jimi Hendrix・Miles Davis本人サイトのフッターがリンクするSonyの利用規約4 B iiには、自動アクセス・取得等を制限する記載がある。調査中に技術的な取得可能性は確認したが、以後の自動取得は許諾確認まで停止した。Sony Japan・Legacyも適用条件の確認待ちとして保守的に停止する。一般向けrobots許可だけを契約上の許諾と解釈しない。

- [Sony利用規約](https://www.sonymusic.com/terms-and-conditions/)
- [Warner利用規約](https://wmg.jp/corporate/terms-of-use)
- [Universal利用規約（Blue Noteからのリンク先）](https://privacy.umusic.com/terms/)

Warner・Blue Noteも公開サービスとしての継続取得・再利用の許諾が確定したとは扱わない。今回の限定的な試作品と、一般公開運用の可否を分ける。本文・歌詞・画像は配信せず、確認に必要な少量の事実・URL・ハッシュのみを出す。

実取得では固定の識別UAを使い、robotsを事前に確認。禁止経路は取得せず、同一ホストの転送先も確認する。401/403/429はホスト単位で停止し、UA変更、別IP、別ドメイン、プロキシへの切替で取得を続けない。利用条件停止、HTTPアクセス制限、通信失敗、根拠不足は別の状態として返す。停止した本人サイトをMusicBrainzのOfficial表記で代替認定しない。今回はMusicBrainzにも問い合わせていない。

Renderで支払方法を設定すると、無料転送量・ビルド枠超過等の課金可能性がある。無料プランを選ぶだけで無条件に費用ゼロとは扱わない。今回は登録・支払情報・サービス作成を行っていない。有料化、秘密情報の登録、公開デプロイは別途承認が必要。

## セキュリティと維持条件

APIはアーティスト名のみを受け付け、任意URLを取得するプロキシにしない。許可済み公式ホスト・HTTPS・転送先・本人名義・ALBUM区分・発売済み証拠を照合。公式発行元の確認がない候補を表示しない。レスポンス上限5MB、12秒タイムアウト、ホストごと1秒間隔、同時検索4件、検索要求上限、日次の公式取得予算を再利用する。SQLite共有接続は並列要求で直列化し、キャッシュの混線を防ぐ。

APIはPagesの正確なOriginのみCORS許可し、ブラウザからの認証情報は送らない。CORSは認証ではなく、コマンドラインからの濫用を防ぐ仕組みではない。本番公開前には、全インスタンスで共有する取得予算・アクセス制御・費用上限の方式を確定する必要がある。ブラウザへAPI鍵やGitHubトークンを埋め込まない。

キャッシュは24時間以内の確認証拠付きデータだけ。失敗時に未確認データへ切り替えず、有効な以前の確認結果がある場合に限り、その確認日と再取得失敗を区別して表示する。キャッシュ保存先の永続性、原資料の書式変更、利用条件の更新も保守対象になる。

## ローカル再現と公開前の残作業

```sh
python -m server.prototype --port 8001
# http://127.0.0.1:8001/ を開き、Willie Nelsonを検索
```

127.0.0.1のみで待ち受ける。本番登録・秘密情報不要。ライブ試験を明示的に再実行する場合：

```sh
python scripts/validate_v089_live.py --output /tmp/record-v089/live.json
# CIのPlaywright/Chrome環境では --browser も指定可能
```

CIのブラウザ試験ではPagesと同じHTTPS Originの画面と実際のループバックHTTP APIを試験用のURL対応付けで接続する。公式サイトへの通信はAPI側から通常のHTTPSで行い、公式サイトのCORSヘッダーは変更しない。これはクラウド上のAPIや公開サイトでの実機検証とは異なる。

承認後のPages用構成ファイルを生成する仕組みも用意したが、今回そのURL設定は公開ファイルに適用していない：

```sh
python scripts/configure_public_api.py https://APPROVED-API-ORIGIN --mode hybrid --output /tmp/record-hybrid.html
```

次は、(1)取得元の継続利用条件・Jimi側の許諾を確定、(2)無料枠の実行環境とキャッシュ・全体予算を選定、(3)本番登録・秘密情報・公開デプロイについて承認、(4)API公開とPagesのhybrid設定を適用、(5)iPhone実機確認、の順。既存 `render.yaml` は旧案のDB必須設定を残しており、今回のローカル試作品をそのまま公開する手順ではない。
