# RECORD v0.70: initial loading and bounded scroll loading

## Changes

Artist selection first requests one browse index page (100 works). If the complete index fits in that page, count, uniqueness, album type and artist credit are checked before sorting/publishing it. No empty decade queries are needed. More than 100 works publishes nothing from the partial probe and returns to the established complete-range strategy. A failed/invalid probe uses that same range strategy; existing full-index fallback remains available. Probe failures are not silently treated as empty discographies. Rate limiting and JSON timeouts remain unchanged.

This benefits small catalogs at a cost: large catalogs incur one extra index request before their first range. Captured Norah Jones (56) and Jeff Beck (74) indexes complete in one browse call; Miles Davis (637) uses the range path after probing. Norah's earlier path needed the pre-1980, 1980s, 1990s, 2000s index requests before the first release page, so that cold path reduces from five main-list requests to two. This is a request-count comparison on captured metadata, not measured real iPhone seconds. Catalog contents and network latency can change.

Optional group relationship lookup from the listening catalog waits until the initial main-list task completes, so it cannot queue ahead of the main list's next index/release request. Optional catalog fetching itself still starts concurrently.

Automatic pagination requires new downward scroll movement and consumes that intent for one batch. Merely rendering an on-screen pagination button no longer triggers an unbounded load chain. Another downward scroll can request another batch; upward movement cancels an unused intent. The native observer uses a 300px prefetch margin. Stale observer instances, changed artist/generation, loading and error states cannot issue pagination. The explicit button remains available; failure never triggers automatic retry. Browser/programmatic downward scrolling also arms the mechanism.

## Validation

Local Python matching 32 tests and all six Node suites pass. New tests replay captured 56/74/637-work indexes, check incomplete probe rejection and verify auto-pagination intent consumption, stale callbacks/generations, upward cancellation and error behavior. Browser regression adds a native-observer scenario: one complete small index, 100 editions, repeated renders with no extra fetch, deliberate scroll to fetch the next 100, no repeat fetch and one visible work card. Existing chronological scroll regression retains its exact first-page assertion, addressing the earlier flaky 100-versus-107 count.

The real-window test uses the full captured Jeff index via the new small path and the captured Miles range via the large path. Existing mobile UI, identity/evidence, links, drafts, backup, chronology and failure cases remain in CI. All external responses in these tests are intercepted/replayed. No latest live data, real image delivery, YouTube playback or iPhone/Safari timing is claimed.

## Limits

Large catalogs pay an extra probe, and source latency/retries remain. This does not claim universal speedup. One completed index can still take time on a slow network. Only initial artist selection probes; changing order retains the existing range/cache path. Scroll tests need browser CI because local Chromium installation is unavailable. This branch is a PR, not a production deployment.
