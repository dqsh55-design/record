# RECORDの画面・読み込み仕様（v0.65以降）

この文書を主画面の継続仕様とする。名義判定は[ARTIST-CREDITS.md](ARTIST-CREDITS.md)、配信盤の照合条件は既存の照合仕様を維持する。以降の機能追加でも初期画面に操作や説明を並べ直さず、必要な情報はアルバム詳細または設定・詳細へ追加する。

## 主画面の構成

1. RECORDの見出し、短い案内、アーティスト検索。
2. 検索候補から対象名義を選択。人物・バンドの取り違えを防ぐため候補選択を維持する。
3. 選択名義の見出しと、**並び順・名義の2つの選択メニュー**。
4. 年代見出しと縦スクロールのアルバム一覧。
5. 追加読み込み、折りたたみの関連バンド名義、折りたたみの「設定・詳細」。

初期値は「古い順」「本人・共同名義」。名義メニューの6項目は、本人・共同／本人／共同／演奏参加／確認待ち／すべての名義を維持する。ボタン列へ戻さない。区分切替で取得済みの範囲を絞り、並び順切替ではその方向の先頭から再取得する。別名義の選択では初期値に戻す。

通常のアルバムカードは、ジャケット、アルバム名、作品の初回発売年、レーベル、名義区分、YouTube Musicリンクに絞る。初回発売年不明を個別盤の再発年などで補わない。国、個別盤の日付、ライブ／編集盤などの分類、曲目、規格・曲数、品番、バーコード、登録ID、名義の詳細、照合根拠、保存リンクの編集は、そのカードの折りたたみ詳細に置く。

同名・国別・再発の発売盤をタイトルで統合しない。IDの異なる盤を保持し、相違は詳細で確認できるようにする。Official、Bootlegなどの判断条件、共同名義の扱い、演奏参加の根拠条件を画面の簡素化のために緩めない。

「設定・詳細」の中に、一覧の情報・取得状況・注意事項、バックアップと復元、以前のYouTube Music一覧・照合ツールを置く。初期状態は閉じる。設定を開く前にバックアップや復元のフィールドを一覧へ挿入しない。関連バンドも一覧の下部で閉じた状態から開けるようにし、既存の別名義選択を再利用する。

長い注記や技術的な件数は折りたたむ。一方、操作に必要な短い読み込み状態、エラーと再試行、演奏参加区分を選択した場合の「全参加作品ではない」という要旨は、その場で表示する。

## iPhoneサイズの操作

320 / 375 / 390 / 430pxで横スクロールを発生させず、一覧の準備後は最初のカードが初期ビューポート内に見える構成を保つ。選択メニュー・入力は16px以上、主要なリンク・ボタン・詳細の開閉領域は44px以上を維持する。これはブラウザのモバイル表示検証であり、全iPhone実機の動作を保証するものではない。

画像の遅延読み込み・寸法確保・失敗時のプレースホルダー・短時間の失敗キャッシュを維持する。画面外カードの`content-visibility`を使うが、対応しないブラウザでも通常の縦一覧として利用できること。

追加取得、参考一覧の更新、遅れて届いた配信カタログで既存の主一覧カードを作り直さない。開いた詳細・入力中の発売盤URL・フォーカスを保つ。カタログの到着後は、既存の厳しい照合条件を通ったリンクと根拠だけを更新する。

## 年代順を確定する単位

v0.63〜0.64の全索引方式に代わり、通常はMusicBrainz検索索引を**初回発売日の範囲ごとに完了させてから**発売盤を表示する。

- 最初の範囲は1980年より前（それ以前の全ての登録年を含む）。
- 1980年代から現在の年代までは10年ごと。現在の年代の範囲は将来側を上限なしにして、未来日の登録も取りこぼさない。
- 新しい順ではこれらの範囲を逆にする。
- 発売年不明はどちらの並び順でも最後の独立した範囲とする。

検索は`arid:<選択ID> AND primarytype:album AND firstreleasedate:[下限 TO 上限]`。年不明は`NOT firstreleasedate:[* TO *]`で取得する。各範囲を100件ずつ取得し、**その範囲の全ページが揃うまではカードを公開しない**。範囲内を初回発売日とIDで並べてから、従来どおり作品ごとの発売盤を100件ずつ取得する。後の範囲の索引は必要になるまで取得しない。検索応答に含まれる未使用の発売盤参照を捨て、実行中の索引・キャッシュには作品のID・作品名・日付・種別・クレジットだけを保持する。

返却された作品のID、Album区分、選択アーティストのクレジット、日付の範囲、件数を検証する。年だけなどの登録済み部分日付も年の境界で扱い、未登録の月日や年を推定しない。発売盤のレーベル・画像・曲目を全作品分先に取得しない。

索引の件数は「確認済み範囲の作品数」、発売盤の件数は「取得済み件数」。どちらも全作品を取得済みという意味にはしない。後の範囲、未確認の演奏参加、画像や曲目まで取得済みと表現しない。

## エラー・更新とキャッシュ

初回の検索索引は1回で失敗を判定し、カードをまだ公開していないときは従来のアーティスト別全索引へ切り替える。この場合は全索引の取得完了を待つ。検索の順序・不完全な範囲で見かけ上早く表示する代替処理は作らない。

すでにカードを表示した後は途中で索引の方式を変更せず、取得済みの範囲を保持して同じ位置から再試行する。範囲内の件数が途中で変わった場合は、その未公開範囲だけ最初からやり直す。ページの重複で索引の件数が不足するときも完了扱いしない。

同じ作品が別の年代範囲にも現れた場合は、登録年が変わった可能性があるため後の範囲を公開せず、その名義の範囲キャッシュを破棄する。「一覧を読み直す」で現在の並び順・名義区分を保って読み直せるようにする。途中へ作品を差し込んだり、同じ作品を別年代で重複表示したりしない。

完成した範囲のメタデータだけを実行中メモリで10分間、最大50範囲保持する。永続保存のキーやバックアップを変更しない。途中の範囲は完成済みとしてキャッシュしない。検索対象・並び順の世代を管理し、古い応答を現在の一覧へ反映しない。

待機中は短い状態、実際の取得位置に基づく進捗バー、装飾用のスケルトンを表示する。架空のアルバムやダミーの取得完了件数を表示しない。通信エラーでは自動追加を止め、短いエラーと再試行を表示する。技術的な詳細は「一覧の情報・読み込み状況」に置く。

## 既存機能と検証の維持

MusicBrainzの発売区分、本人／共同／演奏参加／確認待ち、盤の同一性照合、YouTube Music検索と直接リンクの条件、関連バンドの別名義、localStorageのキーとバックアップ形式を維持する。旧参考一覧のAPI取得はその領域を開いたときに行い、主一覧の待機列を先に占有しない。旧領域を閉じて開き直した場合やエラー後の再試行も維持する。

継続する自動検証は`tests/test_browser.cjs`、`tests/test_credit_attribution.cjs`、`tests/test_chronology.cjs`、`tests/test_ui.py`。年代範囲の後ページに最古の作品があるケース、範囲の更新、失敗から全索引への切替、読み込み中のメニュー変更、年不明、異なる盤、iPhone幅、遅い補助カタログ、入力保持、保存と復元を含める。

## 限界

MusicBrainzの検索索引は本体の更新と同時反映ではなく、複数要求を一つの時点で固定する保証もない。サービス自体の登録漏れや索引未反映を検出・補完するものではない。年代範囲の大きさや空の範囲、ネットワーク障害によっては待ち時間が増える。初回の全索引への切替では従来同様の待機が必要になる。

演奏参加の全件探索、全曲参加の確認、配信の許諾・現在の再生可否の保証は行わない。iPhone実機・Safariの性能は別途確認する。v0.65の検証結果と具体的な計測条件は[V0.65-REVIEW.md](V0.65-REVIEW.md)を参照する。
