# 主一覧の名義判定仕様（v0.64以降）

画面構成と読み込みは [MOBILE-UI.md](MOBILE-UI.md)（v0.65以降）を参照。この文書は、年代順アルバム一覧における名義分類の継続仕様とする。配信盤の同一性・正規性・再生可否の照合とは独立した判定であり、後者を緩めるものではない。変更する場合は分類・取得経路・画面の回帰テストも更新する。

## 識別と分類

選択したMusicBrainzアーティストのIDを基準とし、文字列の名前・アルバム名・`with`や`&`などの表記から名義を推測しない。同じ名前の別IDは別の名義として扱い、別の表記でも同じIDなら同じ名義として扱う。人物・バンドともこの規則に従う。

| 区分 | 必要な登録根拠 |
| --- | --- |
| 本人名義 | 完全なartist-creditに選択IDだけがある。同じIDの重複は別人と数えない |
| 共同名義 | 完全なartist-creditに選択IDと別のIDがある。先頭・末尾などの記載順では除外しない |
| 演奏参加 | 発売盤の完全なartist-creditに選択IDがなく、その盤の収録録音に選択IDの`instrument`・`vocal`・`performer`関係が登録されている |
| 確認待ち | クレジットが欠損・空・不完全、選択IDを含まないが演奏根拠がない、その他判断できない場合 |

「完全」はここでは、空でないartist-creditの全要素にアーティストIDがあることをいう。共同名義の一人が不明な場合も単独名義に丸めず確認待ちとする。正式な本人・共同名義を確認できた作品は、録音の演奏関係も存在するという理由で単なる参加作品へ移さない。

発売盤詳細のartist-credit、発売盤一覧のartist-credit、作品（release-group）のartist-creditの順に参照する。上位のプロパティが存在しない場合に限り下位へ進む。明示的な空配列・不完全なクレジットを下位の都合のよい値で置き換えない。発売盤の別名義を作品の本人名義で上書きしない。作品のクレジットを使う場合は根拠が作品単位であることを詳細に表示する。

## 演奏参加の根拠

作品索引に結び付いていること、artist-creditに名前がないこと、曲の作者であること、所属バンド、プロデュース、編曲、一般的な関連作品情報だけから演奏参加を断定しない。

既存の「曲目を取得」を使い、同じ発売盤詳細を`recordings+labels+artist-credits+artist-rels+recording-level-rels`付きで取得する。収録録音の`relations`で上記3種類の関係と選択IDが一致し、録音IDがある場合に限り演奏根拠とする。曲名・役割・楽器属性と録音の出典URLを表示する。録音ID・役割・属性が同じ根拠は重複表示しない。

一部の録音の根拠から全曲参加とは判断しない。関係がない・不足している場合も「不参加」とは断定しない。正式な発売盤名義が欠けているときは、演奏の根拠があっても名義区分は確認待ちに保ち、根拠だけを表示する。

取得した情報で現在の区分に合わなくなった場合、利用者が読んでいる詳細を保ったまま判定結果の区分へ切り替え、状況を通知する。通信待ちの間に利用者が対象名義・並び順・区分を変更した場合は、古い操作による区分変更を強制しない。演奏の根拠は既存の実行中メモリキャッシュで保持し、保存データ形式は変更しない。

## 表示と読み込み

初期区分は「本人・共同名義」。共同名義を初期一覧から除外しない。「本人名義」「共同名義」「演奏参加」「確認待ち」「すべての名義」に切り替えられる。区分ごとの件数と切替対象は**取得済み**の発売盤であり、全作品数・全参加作品数とは表示しない。

名義切替では同じ取得済みの年代順の範囲を絞り込み、発売盤の再取得や年代の再推定を行わない。並び順切替はv0.63の方式でその方向の先頭から再取得し、名義区分は維持する。名義を新しく選ぶと初期区分へ戻る。

索引はv0.65以降、初回発売日の年代範囲ごとのMusicBrainz検索を完了させてから表示する。検索を利用できない初回は`release-group?artist=...&type=album&inc=artist-credits`の全索引を確定する。詳細な順序保証・障害時の切替は[MOBILE-UI.md](MOBILE-UI.md)に従う。発売盤一覧は従来の`release?release-group=...&inc=labels+media+artist-credits`を100件ずつ取得する。画像・曲目・録音関係を全件先行取得しない。年不明の末尾区分、古い順／新しい順、既存行の再利用、再試行、重複排除、古い通信結果の排除も維持する。

演奏参加区分は、取得済み候補のうち詳細で確認できた盤に限る。空の参加一覧を埋めるための自動全件走査は行わず、同区分では自動スクロール取得を止めて手動追加を残す。参加作品の網羅性を保証しない旨を一覧の情報内に常設し、演奏参加区分を選んだ際は全参加作品ではない要旨をその場にも表示する。

## 関連バンドと互換性

既存の`showRelatedBands`を再利用し、`member of band`関係から別名義へ移動する。所属バンド名義の作品は、メンバー本人の名義へ自動的に合算しない。バンドを選択したときはそのバンドのIDで新しい一覧を開く。

YouTube Musicの本人照合・発売盤照合・期限・曲目／年／レーベルの条件は従来どおり。今回の「共同名義」分類だけを理由に直接配信リンクを採用しない。既存localStorageキー・カタログ形式・バックアップ形式を変更せず、以前の照合・手動登録・保存記録を削除しない。

## 継続する検証

- `node tests/test_credit_attribution.cjs`：ID同一性、表記差、同名別ID、共同名義、欠損、発売盤の優先、演奏関係の許可範囲、所属バンド、区分切替を検証。実APIから取得済みのMiles Davis／Jeff Beckの本人・共同・参加の応答も再生する。
- `python tests/test_ui.py`：初期表示・区分切替・詳細の根拠取得・分類の更新・別バンドへの移動に加え、年代順スクロール・画像・リンク・保存／復元の回帰を検証する。
- `python scripts/validate_v064_live.py`：任意実行の実HTTPS確認。通常のCIでは実APIへ接続しない。実接続の記録と保存応答の再生による模擬テストを混同しない。

## 対象の限界

アーティスト別release-group索引は正式クレジットのある作品の索引であり、全演奏参加作品を発見するサービスではない。今回、他名義の参加作品を全件探索する新しい検索経路は追加していない。Somethin' ElseやAmused to Deathの実取得は、分類規則を確認するために別途作品検索から調査したサンプルであり、通常のアーティスト索引に含まれるという意味ではない。

MusicBrainzは共同編集の登録情報である。今回の分類は法的な名義・演奏実績・正規配信・現在の再生可否を独立に保証しない。
